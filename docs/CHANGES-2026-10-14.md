# Claude Terminals: changes from the 2026-10-14 review

On 2026-10-14 the whole repository was reviewed for defects. Two independent reviewers, Claude and OpenAI's Codex, each checked the other's findings. The review found about 44 problems and ranked them:

- **P1:** reachable in normal use, with data loss, code execution or a broken core feature.
- **P2:** real, with moderate impact or a narrower trigger.
- **P3:** narrow races, native failure paths, hardening and debt.

This document lists every change made as a result, what each change fixes and why it was done this way. The full review, with evidence for each finding, is in [`claudeterminals-review-2026-10-14.md`](claudeterminals-review-2026-10-14.md).

## Things that now behave differently

The fixes are listed below. These are the changes you will notice in use:

- **Shift+Enter** inserts a newline in Claude's prompt again. It no longer submits.
- **Ctrl+V** pastes. It used to send `^V`.
- **"Open" / "Open file"** on a script or executable (`.cmd`, `.bat`, `.js`, `.ps1`, `.py`, `.exe`…) opens it in an editor instead of running it. Paths outside the repository, including via junctions or links, are refused.
- **Dropping files or links** onto the window does nothing. Before, it replaced the app's page.
- **Stop session** shows "[Process stopped — press Enter to restart]", and Enter restarts the session.
- **Undo Changes** refuses rather than guesses when:
  - the files, the last commit, or their unstaged edits changed while the dialog was open;
  - it would overwrite a file that now exists at a deleted or renamed file's old name;
  - git's status output was incomplete.

  When a later step fails after an earlier one changed files, the error says "Undo was only partly applied".
- **Unstaging a rename** unstages both halves.
- **New Session buttons** behave like Ctrl+Shift+N: "New conversation" is selected, other worktrees are listed (except ones whose folder is gone), and the command is remembered.
- **A session command not found on PATH** fails with "'x' was not found on PATH". It is never looked up in the repository folder. `claude.cmd` from npm is found on PATH and run by its full path.
- **The commit message box** keeps its cursor, selection and IME input while Claude works. A commit no longer erases a message typed while it was running.
- **Open diffs and the history view** stay live. The diff refreshes for its own session whichever session the Git panel shows. History refreshes after commits, amends, pushes and pulls.

## PR #1: P1 fixes

### Shift+Enter submitted the prompt
- **What was wrong:** The key handler sent `ESC CR` (Claude's newline) but didn't cancel the browser event. xterm.js then turned the following keypress into a second `CR`, which submits.
- **Fix:** The handler cancels the keydown and also swallows the keypress for Shift+Enter (`app.js` `terminalKey`).
- **Why:** In the real app, one Shift+Enter sent `1b 0d` plus `0d` before the fix and `1b 0d` only after.

### "Open" ran files
- **What was wrong:** Opening a changed file used the Windows default action, so a `.cmd`, `.js` or `.exe` that Claude had written was executed. The path also wasn't checked against the repository.
- **Fix:** A file counts as runnable if its type is:
  - on a script list;
  - in `PATHEXT`;
  - flagged by Windows' own unsafe-type check (`AssocIsDangerous`);
  - or associated with a program that runs it (the default command runs `%1` itself or a known script host).

  Runnable files open with the type's "edit" verb, or Notepad. The path must resolve inside the repository, both as text and after following junctions and links.
- **Why:** Opening a file to read it must never run it. Windows' own risk list is the most reliable base, and the association check catches script types a list would miss.

### Dropping a file navigated the WebView away
- **What was wrong:** Dropping a screenshot or file, a common habit with Claude Code, replaced the whole UI while sessions kept running. Any page loaded that way could also send commands to the host.
- **Fix:** External drops are disabled. Navigation to anything but `https://app.local/index.html` is cancelled. The host ignores messages from, and stops posting to, any other document.
- **Why:** The host only trusts the app's own page. Pasting dropped file paths into the terminal, as Windows Terminal does, would be a separate feature.

### Undo could overwrite or delete the wrong files
- **What was wrong:**
  - Undoing a staged rename restored the old name over any file now there.
  - A failed or partial "is this file in HEAD?" lookup was treated as "not in HEAD", which moved tracked files to the Recycle Bin.
  - The host re-read status and could perform a different action from the one you confirmed.
- **Fix:**
  - "In HEAD" now comes from the same `git status --porcelain=v2` snapshot (each entry's HEAD file mode), and restores use that snapshot's commit.
  - The page sends back exactly what the dialog showed, and the host refuses if anything differs.
  - Restoring over a file at a rename's old name, or at a staged deletion's path, is refused. Case-only renames still work.
  - Copies no longer restore their source.
- **Why:** Undo is destructive, so it does exactly what was confirmed or nothing. One snapshot removes a whole class of "the second lookup failed or saw something newer" problems.

### Stop left the session shown as running
- **What was wrong:** Stopping disposed the process without telling the page. The tile stayed "running", input went nowhere, and Enter didn't restart.
- **Fix:** The host posts an "exited" message after Stop. Each process gets a generation number, so a late exit from an old process can't mark a restarted one as stopped.

### Tests
A new xUnit project, `tests/ClaudeTerminals.Tests`, was added to the solution. Run it with `dotnet test tests/ClaudeTerminals.Tests`.

## PR #2: fixes from the second review of #1

A second review of #1's fixes found these. All are fixed:

- **The Undo dialog sent the commit current at the click, not when it opened.** If the view refreshed to a newer commit while the dialog was open, the "commit changed" check passed. The dialog now captures the commit when it is built. In the real app, before the fix Undo restored from a commit the dialog never showed; after it, the click is refused.
- **Case-only renames.** Whether the file at the old name *is* the renamed file is now decided by the file system's identity of the two directory entries. Spelling isn't enough (folders can be case-sensitive), and neither is following a symlink.
- **Containment compares paths exactly, including case.** In a case-sensitive folder, `C:\work\Repo` and `C:\work\repo` are different folders.
- **"No commits yet" vs "unknown commit".**
  - A missing or invalid commit header in git's output is no longer mistaken for a new repository.
  - Undo only runs on complete, well-formed status output: NUL-terminated, a valid commit id or `(initial)`, and only known entry types.
  - The page receives `(initial)` for a new repository.
- **Partial completion.** When a later git step fails after an earlier one changed files (including git failing to start), or Recycle Bin moves fail, the error says Undo was only partly applied.

## PR #4: P2 fixes

| | What was wrong | Fix | Why this way |
|---|---|---|---|
| **Ctrl+V** | xterm.js turned Ctrl+V into `^V` and cancelled the event, so the browser never pasted. | The key handler lets plain Ctrl+V through uncancelled, so the browser's native paste reaches xterm's paste handler. | The native paste handles bracketed paste and needs no clipboard permission prompt. |
| **New Session buttons** | The click event was passed as the dialog's `mode`. The dialog opened with no mode, no worktree list, and the command was not remembered. | The buttons call `showAddDialog()`. | Same path as Ctrl+Shift+N. |
| **Unstaging a rename** | Only the new path was unstaged. The old path's deletion stayed staged and went into the next "Commit Staged". | Unstaging a staged rename's new path also restores its old path to the index, from the file, folder and "Unstage All" actions. | A rename is two index changes; unstaging half of it silently commits a deletion. |
| **Large Undo/Stage could hang** | Git's input was written before its output was read. Git answering line by line could fill its output pipe and block both sides. | Output and error streams are drained before and while input is written; git quitting early is tolerated. | Standard pipe handling, verified with 20,000 lines of input. |
| **Adding several sessions** | Sessions were added one by one, so an invalid folder left earlier ones hidden and a retry duplicated them. Deleted worktrees were offered. A slow worktree reply could show the wrong folder's list. | Every folder is checked before any is added. Worktrees git reports as `prunable` are hidden. Worktree replies and ticks only count for the folder currently in the dialog. | All-or-nothing avoids duplicate Claude sessions in one folder. |
| **Commands not found as .exe** | npm's `claude.cmd` was started via `cmd /c claude` in the repository folder. cmd looks there first, so a `claude.bat` in the repo would run instead, and quoted paths and arguments could be mangled. | `.cmd` and `.bat` shims are found on PATH (with `PATHEXT`) and passed to `cmd /d /s /c` by full path. A name not on PATH and not a cmd built-in is refused. Relative PATH entries are skipped. | Running a script from the repository instead of the real tool is a code-execution risk. |
| **Commit message box** | It was rebuilt on every status refresh (at least every 15 s while Claude works), so the cursor jumped to the end and selection and IME input were lost. A finished commit cleared a newer message. | The box is created once per session and kept in place while the panel around it is rebuilt. A commit clears it only if nobody typed in it meanwhile; an edit counter is used, so retyping the same text counts. | Moving a focused element out of the page drops focus and IME composition. |
| **Leaked git watchers** | Refreshing twice quickly, or removing a session mid-setup, left an orphaned file-system watcher and a 15 s `git status` poll for the app's lifetime. | Git setup has a generation number and a disposed flag under a lock. A superseded or post-removal setup installs nothing. | |
| **Final output lost on exit** | The exit was reported, and the process cleaned up, before the last output was read. Also, when the app's own output was redirected, child processes wrote there instead of the pseudo console. | On exit the host waits for the output reader to finish. Child processes are started with `STARTF_USESTDHANDLES` and no handles, as Windows Terminal does. | Error messages such as a bad `--resume` id were the output most likely to be lost. |
| **Oversized diffs** | The 4 MB limit was checked after git's output was fully loaded, so large files were read whole (twice) before "too large". | `git show` output is capped at the limit and git is stopped past it. | Rejecting a 64 MB file now allocates a few MB, not hundreds. |
| **Live diff and history** | An open diff refreshed only for the session selected in the Git panel. History didn't refresh on new commits, and stayed on "Loading…" if opened before the first status. | Status updates refresh the open diff of their own session. History is invalidated when the last commit, upstream or ahead count changes (amends included) and reloads on its own. A reply that a newer commit superseded isn't cached. | |
| **Conversation titles** | Transcripts under ~96 KB stopped being read after the first prompt, so later custom titles and last prompts never showed. | The first 96 KB is always read in full. This is your fix from #3, kept as is; #4 adds tests for small transcripts, ones just under and just over 96 KB, and ones with the latest title near the start. | |

A further review of the P2 changes found gaps in some of these fixes, which were then closed:

- **Command lookup:**
  - only fully qualified PATH folders are searched (a drive-relative entry such as `C:tools` is skipped);
  - a found script whose path contains `%` is refused, because cmd would expand it, and cmd runs with delayed expansion off;
  - a dotted name such as `tool.v2` still tries each `PATHEXT` extension.
- **Unstage** refuses, changing nothing, if it can't read the repository's status, rather than unstaging only half of a rename.
- **Git commands:**
  - git is ended as soon as an output limit is crossed, even while it is still being fed input;
  - git is killed if an operation is cancelled or fails part-way.
- **Working-file diffs:** the read is bounded by the 4 MB limit, not checked once beforehand, because the session may be writing the file.
- **Exit reporting:** waiting for final output is bounded at 30 s, so a pipe that never closes can't stop the exit from being shown.
- **Git setup** records the repository root only from the current setup, never a superseded one.
- **History:**
  - every refresh invalidates a history load already in flight;
  - a failed load is shown as an error and retried, instead of being cached as an empty history.

## Not changed (still open)

- **Esc while the terminal's context menu is open** also interrupts Claude. The README says plain Esc always goes to the terminal, so this is a decision for the owner, not a fix.
- **The design of "Open"'s runnable-file check.** It is a deny-list, not a guarantee. The alternative is to always open in an editor, or to reveal in Explorer.
- **Content-level binding for Undo:** an already-modified file gaining more edits while the dialog is open.
- **Millisecond races with another program** writing files between Undo's check and its restore, or swapping a junction during Open.
- **The P3 findings in the review.** Two were fixed along the way: a late exit marking a restarted session stopped (with Stop, in #1) and the redirected-output launch problem (with the final-output fix, in #4). The rest are listed in the review write-up. Malformed bridge messages (F44) are still unhandled, though only the app's own page can now send them.
