# Claude Terminals

One window for many local Claude Code sessions, with a Visual Studio–style Git Changes / Git Repository view and diff viewer for each session's worktree.

- **Host:** .NET 10 WinForms + WebView2 (`src/ClaudeTerminals`)
- **Terminals:** real Windows pseudo consoles (ConPTY) rendered with xterm.js; child processes live in a kill-on-close job object
- **Diffs:** Monaco diff editor themed to match VS dark

## Requirements

- Windows 10 1809+ or Windows 11 (x64)
- [Claude Code](https://docs.anthropic.com/en/docs/claude-code) on `PATH`, plus Git
- To build: .NET 10 SDK and Node.js (for the bundled xterm.js / Monaco packages)
- WebView2 Runtime (built into Windows 11)

## Build / run

```powershell
cd web; npm ci; cd ..               # once: xterm.js + Monaco
dotnet run --project src\ClaudeTerminals
```

Sessions are saved in `%APPDATA%\ClaudeTerminals\sessions.json` and restarted when the app opens. Set `CLAUDE_TERMINALS_DATA` to use a different folder (separate profiles, testing).

## Installer

```powershell
winget install JRSoftware.InnoSetup   # once
.\publish.ps1                         # -> artifacts\ClaudeTerminals-Setup-<version>.exe
.\publish.ps1 -SkipInstaller          # -> artifacts\publish\ (portable folder only)
```

- Self-contained x64 build (no .NET install needed). The version comes from `<Version>` in `ClaudeTerminals.csproj`; bump it for each release.
- Installs per-user to `%LOCALAPPDATA%\Programs\Claude Terminals` (no admin), with a Start Menu shortcut, an optional desktop shortcut and an uninstaller. Admins can choose an all-users install.
- Upgrading: run the newer setup. It asks to close a running copy first. Saved sessions are kept; uninstalling also keeps them in `%APPDATA%\ClaudeTerminals`.
- Setup warns and links to the download if the WebView2 Runtime is missing (it's built into Windows 11).
- Local builds aren't code-signed, so on other PCs SmartScreen shows "unknown publisher" (More info → Run anyway).
- **Signed releases** are built by `azure-pipelines.yml` on the agent with the company's code signing token: push a tag `v<version>` matching `<Version>`, and it runs `publish.ps1 -Sign -TimestampServer <url>`, which signs `ClaudeTerminals.exe`/`.dll`, setup and its uninstaller as *Llamachant Technology Ltd* (picked from the certificate store by subject, as the NuGet signing does) and fails unless every one carries a valid, timestamped signature from that publisher. The pipeline then creates a draft GitHub release with the installer; publishing the draft is what makes the in-app updater offer it.
- Only one copy runs at a time; launching again brings the existing window forward.
- The icon is generated by `tools\make-icon.ps1`.

## Using it

| Action | How |
|---|---|
| Expand a session | Click its tile, its tab in the title bar, or press `Ctrl+1`…`Ctrl+9` |
| Back to all sessions | Click the open session's tab again, `Shift+Esc`, the collapse button in the tile header, or the mouse Back button |
| Next / previous session | `Ctrl+Tab` / `Ctrl+Shift+Tab` |
| Toggle Git panel | `Ctrl+Shift+G` |
| New session | `Ctrl+Shift+N`: start a new conversation (optionally one session per worktree) or **resume an existing conversation** |
| Switch a session to another conversation | Session menu (⋯) → *Resume a different conversation…* |
| Close a session | The × on its tab in the title bar, or middle-click the tab. After you confirm, the session is removed and its process stopped; the folder isn't touched |
| Show one project | Ctrl+click its name in the Projects row, or right-click it → *Show only this project* |
| Show several projects | Click a project's name or checkbox to show or hide it; **All** shows every project, **None** hides them all |
| Put a session in a project | Pick the project when adding the session, drag its tab into the project's group, or right-click its tab → *Move to project…* |
| Reorder tabs | Drag session, project or diff tabs (or right-click → *Move left/right*). Unknown stays last and the Terminal tab first |
| Rename, recolour, reorder or delete a project | Right-click the project. *Edit project* sets its name and colour (a swatch, a custom colour or Automatic). Deleting it keeps its sessions; they just have no project |
| Terminal font size | `Ctrl+=` / `Ctrl+-` / `Ctrl+0` |
| Newline in Claude prompt | `Shift+Enter` |
| Copy / paste | `Ctrl+C` with a selection / `Ctrl+V` (or right-click when expanded) |
| Look back through the conversation | Hover the ticks at the right edge of the open terminal; click one (or right-click → *Show conversation*) to open the **Conversation** tab at that prompt |
| Diff tabs | Click a file for a preview tab (italic, reused); double-click to keep it open. Tabs belong to their session's project: switching to a session in another project shows that project's tabs, and yours come back when you return |
| Terminal ↔ diffs | Click the Terminal tab, `Shift+Esc` from a diff, or `Ctrl+PgUp` / `Ctrl+PgDn` |
| Close diff tab | `Ctrl+W` or `Ctrl+F4`, middle-click, or the tab's ×; `Alt+↑/↓` jumps between changes. (In the terminal `Ctrl+W` stays Claude's delete-word) |

Plain `Esc` always goes to the terminal, because Claude Code uses it to interrupt.

**Tile status dots:** green = idle, pulsing blue = working, orange = finished working while you weren't watching (or rang the bell).

**Projects** group sessions, for example everything for one product across its worktrees. Only the ticked projects' sessions are shown. Sessions with no project are grouped under **Unknown**, which you tick and untick like a project. Each session's tab and tile carry a tag in its project's colour, so two sessions with the same name in different projects can be told apart. Hidden sessions keep running, and each project tab counts its sessions waiting for you, so a hidden project still gets noticed.

**Git panel:** shows the selected session's repository. *Git Changes* has staged/unstaged trees, stage/unstage, commit, and VS-style **Undo Changes** (right-click a file or folder, or the ↶ on a section header; new files go to the Recycle Bin; it refuses rather than guesses if the files changed after you confirmed, or if restoring would overwrite a file that now exists at a deleted or renamed file's old name). **Suggest** writes a commit message for what Commit would take (the staged changes, or all of them), in the style of the repository's recent commits; Ctrl+Z brings back what was in the box. It runs Claude Code headless (`claude -p`, Haiku, no tools, not saved as a conversation) with your own Claude sign-in, sending it the diff. *Git Repository* has outgoing commits and history, plus each commit's files. Click any file to open a diff. Open diffs refresh as the session edits the file.

**Fetch, Pull and Push** sit on the Git panel's toolbar, next to the branch and its outgoing/incoming counts. Pull only fast-forwards: it never creates a merge commit or leaves conflicts in a worktree a session may be editing, and stops with git's explanation if the branch has diverged. Push never forces; a branch with no upstream is published to `origin` and tracked. Each runs for up to 5 minutes, long enough to sign in through Git Credential Manager.

**Pull request chip:** when the branch has an open pull request on GitHub or Azure DevOps, a **PR 958 ▾** chip appears next to it, with *Open in Browser*, *Refresh*, *View Pull Requests* and *New Pull Request*. To find it the app calls that service's API with the credential Git Credential Manager already holds for the remote: it is only sent to that service over HTTPS, the lookup never opens a sign-in window (without a stored credential there's simply no chip), and results are cached for 3 minutes.

**Conversation rail and tab:** the ticks down the right edge of the open terminal are the prompts you've sent in that session, newest at the bottom. Hovering one shows the prompt and the start of Claude's reply; clicking opens the session's **Conversation** tab next to the diff tabs, scrolled to that prompt. It shows the whole conversation as text: your prompts, Claude's answers with their formatting, and its tool calls (long runs folded). It follows along while Claude works, and its own rail jumps between prompts. Both come from Claude Code's saved transcript (the session's Claude process names it in `~/.claude/sessions`), so they work in Claude's full-screen mode, which keeps no terminal scrollback. Nothing is sent anywhere.

**Theme:** *System*, *Light* or *Dark*, from the theme button (the palette next to the version number at the top right). *System* (the default) follows Windows' app mode (Settings › Personalisation › Colours), and changes with it. The terminals go light too, and each Claude is started in its matching theme (`--settings` with `{"theme":"light"}` or `"dark"`): Claude can't detect the terminal's colours itself, because the Windows console layer doesn't pass the question through. Sessions whose command passes its own `--settings` are left alone. Claude reads its theme when it starts, so after switching, the app offers to restart running Claude sessions; each carries on in its conversation.

**Colours:** by default the app uses your Windows accent colour (Settings › Personalisation › Colours) for tabs, buttons and highlights, and follows it when you change it. To pick another, use *Accent colour…* under the theme button: Windows accent, the original purple, eight swatches or any custom colour, previewed as you click (Cancel or Esc puts back what you had). Shades are chosen so white text and the background stay readable in both themes, so a very light or dark colour is toned where needed.

**Updates:** a few seconds after starting, and every 6 hours, the app checks this repository's latest GitHub release (an anonymous request; nothing about you or your sessions is sent). When there's a newer version, an **Update to x.y.z** button appears in the title bar, showing what's new. *Update and restart* downloads the installer, checks it against the SHA-256 GitHub publishes for it (it won't run a file that doesn't match), closes the app, installs silently and reopens it. Running sessions carry on in the conversations they were in. The version is shown at the right of the Projects row and in the window title; clicking it offers *Check for updates* and turns the automatic check off.

**New sessions continue by default:** their command is `claude --continue`, so restarting the app (or a session) carries on the folder's last conversation. When the folder has no saved conversation yet, the app starts plain `claude` instead of letting Claude stop with "No conversation found to continue"; the command keeps `--continue` for next time.

**Resuming:** the picker reads Claude Code's saved conversations from `~/.claude/projects`. A resumed session keeps `claude --resume <id>` as its command, so it reopens the same conversation every time the app starts. Close the conversation in any other terminal first. Conversations updated in the last few minutes are tagged *active now* as a reminder.
